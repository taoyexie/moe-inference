目标仍为固定成本基线与完整 KITE 的真实端到端对照，不要求消融。

## 已核对与证据边界

| 项目 | 本次结论 | 证据与限制 |
|---|---|---|
| 两组对照 | 同一执行器、请求、预算、精度、fallback 和启动流程 | 代码及本地回归；不冒称原始 WiSP |
| 真实执行 | 完整模型与 router、独立请求位置/KV、物理池容量改变 | 旧小场景服务器已运行；新版长场景尚未完成 GPU 数值门禁 |
| 成本和 miss | 四路径标定；历史 LRU reference 与实际 bypass 分开记录 | reference 不是实际非准入缓存的精确模拟 |
| 启动和计时 | 启动标定、池初始化、调整、搬运、推理、在线决策计入 E2E | 模型加载另列，同时保留程序总时间 |
| 忙卡保护 | CUDA 前预检；模型加载前启动监控；保存 PID 原始查询 | 轮询不是预约，不能排除所有瞬时干扰 |
| 稳健标定 | 先按每个 x 取中位数，再拟合及检查 | 修复先做普通拟合可能提前失败的问题；全部原始样本仍保留 |
| KV 工作区释放 | 临时缓存对象不再通过类闭包延迟持有 dense KV | 关闭自动垃圾回收的弱引用测试通过；不是 CUDA 峰值实测 |
| 结果审计 | 校验源码、协议、请求、计时、真实 miss、数值检查与资源记录 | 正式两组跑完后仍需离线审计 |

当前本机完整回归 129 项通过。无本地 Torch/GPU，使用逻辑测试、模拟接口和 NumPy 张量，
不能把它们称作 A100 数值或性能验证。源码包还要在封包后做独立解压与测试。

工作区释放的对照验证：关闭自动 GC 后，归档 v1 的临时 KV 工作区仍被类闭包持有，
只有显式 GC 后释放；新实现丢弃缓存对象后即释放。验证使用 NumPy 模拟张量，
不据此声称已测得显存下降或加速。

## 空闲后的一次执行链

1. 上传 v2 包并解压，可提前完成；不重装依赖、不重下载权重。
2. 运行 `check`；忙卡显示 `blocked` 是预期结果，先等空闲。
3. 运行一次 `search --seed 17`：再次预检 → CUDA 小检查 → 启动资源监控 → 加载模型 →
   必要短数值检查 → 两组各自标定和完整生成 → 保存实际耗时。
4. 下载完整结果并审计。短数值检查失败、OOM、干扰或整体无收益时先读记录，不自动追加扫描。
5. 只有整体正收益且审计通过，才冻结该版本，换预留主题执行三次独立确认。

具体命令、含义与执行位置见 [运行指南](KITE_ADVANTAGE_GUIDE.md)。

## 仍须空闲 GPU 验证的三件事

1. 新注意力实现与恢复路径的短完整模型数值检查。
2. 11264-token 混合批次的实际显存/主存峰值和运行稳定性。
3. 包含自身启动标定的 KITE 整体净加速，不能由 miss 或局部路径计时替代。

长上下文超出初始 KV 标定域，按规则保守 restore；虽然四路径都有实现和启动验证，
不预先声称正式长场景会选择 KV recompute。CPU 冷转换和 CPU FP32 副本上限也真实计入。
