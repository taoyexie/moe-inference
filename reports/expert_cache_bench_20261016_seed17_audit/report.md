# 专家成本选择配对实测核验（2026-10-16，seed 17）

同一 A100、同一真实 Qwen 专家内核、相同两个 GPU 权重槽。10 组随机交错正式配对，每个 pass 192 次调用，缓存从空开始，计时中无逐调用参考检查。

| 场景 | 固定成本平均 ms | 线性成本平均 ms | 平均配对耗时降低 | 正收益配对 |
|---|---:|---:|---:|---:|
| 异构 q + 缓存压力 | 85.948 | 46.775 | 45.57% | 10/10 |
| 小 q + 缓存压力 | 85.359 | 60.145 | 29.54% | 10/10 |
| 稳定热点对照 | 23.099 | 23.066 | 0.14% | 6/10 |

## 为什么主场景有利

每轮 A(q=32)、B(q=1)、C(q=1)，三专家竞争两个槽。固定成本模型在这次标定下选择 upload，导致循环淘汰，192 次调用均为 upload miss。线性模型仅首次上传 A，随后 A 命中 63 次，B/C 共 128 次走 CPU，不污染 GPU 缓存。它利用的是计算量异构与 CPU bypass 的共同收益，不能单独归因于拟合精度或 phase 修正。

小 q 场景线性模型所有调用都走 CPU，固定模型均 upload；稳定热点场景两种模型均首次上传两次、随后命中 190 次。稳定热点变化很小且配对有正有负，不作为加速结论。

## 开销和核验

启动 Expert-only 标定（含标定预热/数值检查/拟合）226.089 ms；完整比较程序 11.161 秒。主表不含槽初始化/释放和启动标定，不表示工作负载含启动端到端时间。

槽初始化、执行和释放均另有计时，详见 audit.json；若仅在线性方案单独计入本次全部标定开销，主场景需约 6 个同长度 pass 才能按本轮平均执行差额摊平，属于算术估算、不是新的实测端到端收益。

核对 66 个 pass，11520 次正式调用的汇总计数，1152 次详细状态转换与时间，58 次数值检查。最坏 relative L2=0.004227，normalized max=0.005495。

GPU cache 18 MiB，独立 scratch 9 MiB；CPU FP32 权重副本、I/O 和预置输入另计。数值比较仅为前后已选输入和标定检查，未对每次正式调用都重算输出。

## 可用表述

在构造的路由 token 数异构及专家缓存压力场景下，基于 routed-token 数的路径成本模型，相较使用相同标定样本的固定成本模型，将每 192 次专家调用的平均执行时间从 85.948 ms 降低至 46.775 ms；10 组配对测量的平均耗时降幅为 45.57%。该结果来自真实专家权重与算子执行，说明按计算规模选择 CPU 回传或权重上传路径可减少不必要的搬运和缓存污染。

上述可用表述须附硬件、CPU FP32/GPU BF16、受控输入构造、缓存容量、计时边界与标定开销。该场景依据此前结果主动选取，不是自然请求 trace 或盲测；单进程重复尚需独立会话复测。不能将 45.57% 写成完整模型 TTFT、KITE、phase-aware 或原始 WiSP 的提升。
