## 一 交付范围

最小交付包含实验设置表、真实访问特征图、两类路径的计时图、分配对照表及原始日志。
不以达到某个预期提升比例作为完成条件。

| 证据 | 数据来源 | 能支持的表述 |
|---|---|---|
| Expert 访问与 routed tokens | 真实模型的非空 Expert 调用 | 指定请求集上的 P/D 访问特征 |
| KV 长度和占用 | 真实 K/V 张量及缓存状态 | 上下文与 KV 容量的关系 |
| 四路径完成时间 | 真实权重、激活、KV 的执行与搬运 | 指定硬件和恢复边界下的路径代价 |
| cache miss 数和候选 split 成本 | 真实 trace 驱动的指定缓存重放 | 指定缓存策略下的分配决策差异 |
| TTFT、TPOT、吞吐改善 | 仅在实际接入 allocator 后配对推理 | 实测端到端性能改善 |

最后一项是扩展项，不能用恢复成本重放代替。模拟 miss 不能称硬件实测 miss；
由 attention 语义导出的 KV block 需求不能称物理 GPU 地址 trace。

## 二 主模型和资源预算

已核对官方 Qwen 配置：48 层、每层 128 个 Expert、每 token 选择 8 个，
hidden size 2048、Expert intermediate size 768、4 个 KV heads、head dimension 128。
BF16 下单 Expert 的三组矩阵为约 9 MiB；全部 Expert 权重约 54 GiB。
全模型权重约 61 GB 十进制，单 A100 40GB 不能全部常驻。

采用主存卸载先运行真实模型，不默认启用量化或磁盘卸载。
加载时使用内存受控映射，GPU 权重预算暂以 24 GiB 为起点，
最终值依据当时可用资源与峰值调整；给 KV、激活和临时空间留余量。
CPU 预算依据 MemAvailable 和容器限制确定，不以 125 GiB 总容量代替可用量。
不得在加载过程中无意保留两份完整权重或两份全模型 FP32 CPU 权重。

资源检查阶段还需确认 cgroup memory/CPU 配额、当前 GPU 使用与数据盘容量。
允许 CPU affinity 不等于独占资源；试跑先使用 GPU 邻近节点的 8 个线程，
正式计时记录其他负载，后续仅在必要时比较 8/16 线程。

加载预算与 allocator 的可分页 Expert–KV 预算是两个不同参数。
后者从扣除固定权重、激活及预留空间后的独立容量池中取值。

## 三 执行阶段

### 阶段 0 整理项目和固定实验口径

工作内容：保存本计划，区分旧模拟、旧 OLMoE 采集器和新 Qwen 工作。
确定对象粒度、计时起终点、路径精度、P/D 信号定义和结果命名。
不把另一项层感知 KV 复用技术的实验写进 KITE。

产物：README、工作计划、环境与实验配置。
通过条件：每个拟写结论能对应到明确的实验或标为尚未测量。

### 阶段 1 Qwen 加载和一次真实生成

工作内容：编写 Qwen 适配器，固定 Transformers 与 Accelerate 版本，
解析并保存 checkpoint revision；下载只到数据盘。
启用 BF16 和 SDPA，关闭 thinking，使用固定生成配置。
先一条短输入、最多 8 个输出 tokens，不先跑完整请求集。

使用现成 CPU offload 仅解决加载和基础推理。
它不等于 KITE 的 Expert LRU，也不等于 CPU 计算后回传或 KV restore/recompute。
保存 device_map，明确哪些模块常驻、哪些模块临时传入 GPU。

产物：加载日志、软件版本、模型 revision、device_map、显存和主存峰值、生成文本。
通过条件：没有 OOM，没有隐式 disk offload，输出正常，缓存能延续到 Decode。

### 阶段 2 真实路由与 KV 观测

工作内容：对实际执行的非空 Expert 模块加记录，记录层/专家 ID、
调用顺序、routed-token 数、权重 bytes、请求/批次 ID、P/D 标签与上下文。
Prefill 和 Decode 共享同一资源访问序列，不建两个互不共享的物理缓存。
验证每层 routed tokens 合计等于该次 query tokens × 8。

KV 初期只记录真实 K/V 的形状、长度、精度和 bytes。
需要 block trace 时，另外明确 block 管理器及 attention 逻辑读取顺序，
不把长度计数伪装成记录到了真实 block 读操作。
采集 hooks 的计时单独标注，不能同未加 hooks 的运行比较速度。

试运行通过后，使用 30 条明确来源的请求：128/512/2048 tokens 附近各 10 条，
每条最多输出 64 tokens。保存精确长度、原始文本与生成 token IDs，
EOS 提前结束也记录。长度截断或构造策略公开，不声称天然用户请求分布。
将标定与最终评价请求分开；没有公共数据集时可用手写请求验证流程，
但不能将两条手写 smoke prompts 当正式工作负载评测。

产物：request records、Expert trace、KV snapshots、访问特征与 MRC 图。
通过条件：真实输入可复现、路由计数守恒、缓存长度正确、记录粒度和执行器一致。

### 阶段 3 四条路径实测与特征模型

同一任务的起点和终点一致：Expert 两路径以输入位于 GPU 起始，
以结果在 GPU 可用结束；KV 两路径均恢复同一请求的同一个缓存对象。
预分配与计时内分配的边界必须一致，并写入日志。

Expert：先从早/中/晚层各取一个真实 Expert 试测，再扩大到 8 个跨层样本。
CPU 线程固定，q 扫描为 1/2/4/8/16/32/64/128；
输入取真实路由激活，补充拼接或重采样的点明确标记。
GPU 用 BF16，CPU 如采用 FP32，则只保存少量样本的 FP32 权重，
输入/输出格式转换计入完整 CPU 路径，并检查输出误差。

分别报告 Expert 权重纯 H2D、常驻 Expert 的 GPU 计算时间、
upload+GPU 的完整时间、CPU 输入 D2H+计算+结果 H2D 的完整时间。
固定大小 upload 的纯搬运近似常数不代表 upload+GPU 的总时间严格为常数。
若按额外 miss penalty 优化，需在两种 fallback 上统一扣除同任务的 hit 计算基线，
不能把一条路径的纯传输与另一条路径的完整计算不加说明地比较。

KV：暂定某请求固定 128-token 区间跨全部 48 层的 BF16 K/V 为一个对象，约 12 MiB。
在 512/1024/2048/4096 上下文下测同样长度的末端对象。
Restore 真实搬运该对象；Recompute 明确从哪个前置状态重算至哪个位置，
保存 token/position IDs 和数值误差。没有合法前置缓存时须真实重算前缀，
不能只测一层投影并声称恢复了全层 KV。
若完整重算触发内部 Expert upload，按宏操作计一次，
不能在联合成本中再加同一内部 Expert miss；同时恢复多个 block 的共享工作也只计一次。
重算对象和附带产生的前置 KV 是否准入必须明确，不能暗中改变缓存语义。

每点预热 5 次、重复 30 次，完整会话重复 3 次，路径执行顺序交错或随机。
保存每次 wall time、完成同步、精度、bytes 和异常。报告 median、P10/P90，
独立会话与重复 trial 不混为同一统计单位；不测重叠和 exposed latency。
用标定样本拟合常数或线性模型，另留测试点报告误差；非线性明显时如实记录。
不以出现交叉点、线性拟合成功或 proposed 获胜为验收要求。

产物：原始计时、路径正确性记录、cost calibration、Expert/KV 两张路径曲线。
通过条件：同一恢复任务、边界一致、误差在预先声明的容限内、模型误差有记录。

### 阶段 4 分配效果对照

先完成 trace 驱动的四组对照：Fixed+History、Fixed+P/D、Path+History、Full。
四格拥有同一 fallback 集合，统一精度、字节容量、执行模型、
候选 split、初始 cache、准入、warm-up 和 resize 语义。
WiSP 原始路径集合若另测，作为单独系统机制对照，不能混进纯 cost-model 消融。
固定成本由独立标定数据确定，不从测试结果反向挑最优常数。

保留用户设计：统一资源历史 MRC 得 history proposal；
当前已排程 P/D 构成得 current proposal；按固定权重融合并投影到可行容量。
不把原模拟中按 phase 分桶的 rate 预测未经说明地替换进当前设计。
第一版将 P/D 信号定义为批次的 Prefill/Decode 请求组成，
同时保存 token 构成以解释差异；不按执行时间划分 phase。
融合 current 权重 0.65 作为固定起点，标定阶段若需调整，冻结后才评价。

有真实混合调度器则记录实际批次；没有时，使用受控交错重放，
明确其调度是构造的，不宣称已经实测 mixed-batch serving。
决策只读过去访问和执行前已知的批次元数据，不读取下一批的对象 ID、
真实 routed tokens 或真实 misses。未知 routed tokens 用历史估计，
路径真正执行时才允许使用 router 已产生的实际 q。

候选总分页预算先考察 4/8/12 GiB，均需扣除常驻部分并验证可行。
在每个预算内扫描相同的 Expert/KV 字节 split，记录取整 slack 和不可行候选。
LRU 用独立实现核对；P/D 共用每资源的 recency order。
使用 warmed counterfactual MRC 的结果明确标注，不模拟免费扩容填充。
若实现真实闭环，扩容 admission、迁移与 transient 必须真实执行和统一计费。

成本曲线应使用一致的额外 miss penalty 或完整计费模型。
KV 宏重算内部代价与共享恢复不重复计费。若独立可加总假设不成立，
先交付 Expert 局部对照与实测 observation，修正计费后再给联合收益数字。

产物：每窗冻结决策、MRC、miss/cost/split、四组表或图及对照说明。
通过条件：未来信息不泄漏、同样预算与路径、成本可从日志重算、实际/重放边界明确。
若写端到端速度结论，另加真实分配+fallback 的独立配对运行，不沿用重放计时。


远程代码、模型 cache、环境和结果放到 `/data2/xty/epkv`，容器内为 `/workspace`。
原始数据与权重不提交到 Git；小型配置、代码、来源和汇总脚本可提交。
