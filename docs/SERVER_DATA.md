# 服务器数据在实验完成后的处理

## 这次清理的范围

本次只整理 Windows 本机 `D:/moe inference/`，没有连接服务器，也没有移动或删除 `/data2/xty/epkv/` 下的任何文件。服务器上已有的脚本、安装包、模型和结果保持原样，本地清理不会同步删除它们。

容器内 `/workspace` 对应服务器的 `/data2/xty/epkv`。其中的文件在数据盘上，不是只存在于容器内；停止容器不会删除这个挂载目录。Python 实验正常退出后，其占用的 GPU 显存和进程内存通常会释放，但模型文件、日志和结果仍在磁盘上。

## 完成一轮实验后先保留什么

| 服务器项目目录内的内容 | 实验结束后的处理 |
|---|---|
| `models/Qwen3-30B-A3B/` | 继续保留，下一轮直接复用；模型约 57 GiB，删除后要重新下载和校验 |
| `.venv/` | 保留，避免重新配置 PyTorch 等依赖 |
| 最新正在使用的源码目录及原始 zip | 保留，用于定位确切版本和重新运行 |
| 对应的完整 `results/` 子目录 | 整个下载并备份，不只保存终端截图或最后的 summary |
| 原始路由、批次、恢复事件、标定、资源采样、时钟、请求与配置文件 | 与结果目录一起保留，支持后续复核和修改专利图表 |
| 失败、负收益和旧对照记录 | 可以压缩归档；不要在下载和验证前删除，也不要覆盖成新实验的结果 |
| 不再使用的旧源码解压目录和重复上传 zip | 核对版本与备份后可清理；它们通常远小于模型，不急于删除 |

本地已经下载过的一些结果，不等于服务器上的所有文件均已备份。尤其是新跑完的 WiSP 式对照，必须单独下载，不能用旧四路径对照结果替代。

## 推荐的收尾顺序

1. 等自己的实验正常完成，记录它打印的完整结果目录。不要退出仍在前台运行的实验来“清理”。
2. 下载该结果目录的全部文件，同时留存本次源码 zip、模型版本清单和依赖版本。
3. 对下载结果进行核验；能重新读取计时、批次、恢复和配置记录后，再考虑远程清理。
4. 对重要结果保留本地与服务器两份，条件允许时再放一份独立备份。归档不是性能数据重跑。
5. 不再有自己的任务时可以停止自己的容器。模型和结果留在挂载数据盘上；不用为了释放 GPU 而删除磁盘模型。
6. 如确实需要释放数据盘，先列出自己目录的大小，确定具体旧目录后再清理。不要删除其他人的目录，不运行全局 Docker 清理，不重建整个服务器环境。

现在无需删除任何服务器数据。下一次整理服务器时，先核对实际目录清单和占用，再逐项决定；本说明不执行任何远程删除或停止容器操作。
